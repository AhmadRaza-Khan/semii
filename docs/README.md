# semii documentation

semii generates idiomatic, standard-library Go for HTTP APIs and then gets
out of the way: everything it writes is yours to edit, and nothing is
loaded or rewritten at runtime.

- [Getting started](getting-started.md): from `semii new` to an
  authenticated CRUD API in a few minutes.
- [CLI and generators](cli.md): every command, flag and field type.
- [Deployment](deployment.md): Docker, systemd, PM2, Nginx and CI.
- Packages, usable on their own as well as in generated apps:
  - [web](packages/web.md): router, errors, JSON, pagination, middleware
  - [auth](packages/auth.md): principals, policies, JWT, sessions, API keys, passwords
  - [config](packages/config.md): typed configuration from env and `.env`
  - [validate](packages/validate.md): struct validation with JSON field names
  - [db](packages/db.md): pgxdb, sqldb, mongodb and migrate
  - [server](packages/server.md): run, health and graceful shutdown
  - [logx](packages/logx.md): slog setup and request loggers
  - [testkit](packages/testkit.md): HTTP client, assertions and test databases
  - [banner](packages/banner.md): the semii leaf in the terminal

## Principles

1. Standard library first: `net/http`, `http.ServeMux` patterns,
   `log/slog`, `database/sql`.
2. Generated code is your code. Files start with
   `// Code generated by semii … You own this file; edit freely.`
3. No hidden magic: no reflection-driven routing, decorators, `init()`
   registration or global state. Wiring is explicit constructor calls in
   `internal/app/app.go`.
4. Secure by default: every route needs `Public()` or `Require(...)`,
   cookies are `HttpOnly`/`Secure`/`SameSite`, tokens are short-lived and
   only their hashes are stored.
